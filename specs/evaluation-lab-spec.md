## Problem Statement

Autonomous multi-agent trading systems and financial LLM frameworks in the open-source ecosystem suffer from four fatal scientific and architectural flaws:
1. **Uncontrolled Look-Ahead Bias:** Data ingestion layers lack strict point-in-time (`as_of`) isolation, allowing agents to observe future prices, revisions, and post-close news, rendering backtests and performance claims fictional.
2. **Missing Deterministic Baselines:** Complex multi-agent LLM systems are rarely evaluated against simple, zero-cost rules (such as SMA/RSI crossovers or Buy & Hold) under identical execution parameters, masking whether LLMs actually add signal.
3. **Unjustified Agentic Complexity & Cost:** Multi-agent architectures (specialists, debate rounds, consensus mechanisms) incur significant latency and token costs without empirical ablation testing to measure whether the added complexity produces a risk-adjusted alpha delta.
4. **Lack of Provable Lineage & Replayability:** Experiments cannot be verified or reproduced because input bar windows, indicators, prompt hashes, raw model completions, and parsed signals are not immutably persisted or runnable offline without external API credentials.

---

## Solution

QuantAgent is an open-source, reproducible evaluation lab and benchmarking platform that measures whether structured LLM agent workflows earn their cost and complexity over deterministic financial baselines under strict zero-leakage point-in-time constraints.

The platform provides:
1. **Zero-Credential Offline Replay Mode (`pnpm demo:replay`):** A fully deterministic, sub-second execution engine using frozen historical datasets (AAPL, NVDA, SPY) and cached LLM traces at $0.00 cost.
2. **Strict Point-in-Time Temporal Guard (L0):** An automated anti-leakage verification suite that enforces `T_data <= T_decision` across price bars, Benzinga news, and macro probability data, failing builds immediately upon violation.
3. **Head-to-Head Baseline Comparison (L1–L2):** Simultaneous simulation of Buy & Hold and SMA(20/50)+RSI(14) rule engines alongside LLM agent strategies under identical execution conditions (1-bar delay, slippage, 5 bps fees).
4. **Consensus & Ablation Harness (L3–L4):** Deterministic agreement short-circuiting paired with conditional single-pass debate synthesis vs. deterministic neutral-abstain fallbacks to measure the true value of debate.
5. **Observatory UI & Decision Lineage Inspector (L5–L6):** Interactive web dashboard displaying comparative equity curves, risk-adjusted metrics (Sharpe, Sortino, MaxDD, Brier score), operational telemetry (cost, latency, error rates), and full decision DAG provenance for every historical decision point.

## User Stories

1. As an AI researcher, I want to run a complete evaluation sweep over a 1-year historical dataset without external API credentials, so that I can reproduce published benchmark results locally in under 3 seconds at zero cost.
2. As a quant engineer, I want every data query to enforce an immutable `as_of <= decision_timestamp` filter, so that look-ahead bias and post-event data leakage are mathematically impossible.
3. As a CI/CD engineer, I want an automated unit test that attempts to inject future-timestamped data ($T+1$) into a decision query ($T$) and verifies the system throws a `TemporalIntegrityViolation`, so that future leakage regressions immediately break the build.
4. As an applied AI engineer, I want the technical indicator values (SMA, EMA, Wilder RSI, Bollinger Bands, MACD) to be calculated by deterministic code rather than LLM reasoning, so that mathematical ground truth is guaranteed.
5. As a researcher, I want every LLM workflow to run side-by-side against Buy & Hold and SMA/RSI deterministic baselines under identical execution rules, so that I can measure the exact alpha delta generated by agent reasoning.
6. As a quant developer, I want backtest fills to occur at the open price of bar $T+1$ with a 5 bps fee deduction, so that execution delays and transaction friction are realistically accounted for.
7. As an AI engineer, I want specialist agent outputs (Technical, Sentiment, Prediction Market) to be validated against a strict Zod contract (`bias`, `confidence`, `rationale`), so that invalid completions never corrupt evaluation runs.
8. As a platform engineer, I want agent timeouts or schema parse failures to fail gracefully to a neutral stance (`bias: neutral, confidence: 0.0`), so that unhandled model failures do not crash entire evaluation sweeps.
9. As a cost-conscious developer, I want the system to detect unanimous specialist consensus and fast-pass the signal without invoking a debate LLM, so that redundant token consumption and inference latency are minimized.
10. As a researcher, I want an explicit "Debate OFF" ablation mode that deterministically defaults to neutral/abstain upon specialist disagreement, so that I can isolate the counterfactual value of LLM debate synthesis.
11. As a macro researcher, I want a Polymarket prediction odds specialist agent that can be toggled on or off, so that I can evaluate whether crowdsourced macro probabilities improve risk-adjusted returns over news sentiment alone.
12. As an auditor, I want every completed evaluation run to generate an immutable JSON Experiment Manifest containing dataset hashes, prompt hashes, hyperparameter configurations, and financial metrics, so that every experiment has tamper-evident provenance.
13. As an evaluator, I want a Decision Lineage Inspector in the UI that displays the raw input bars, indicators, news items, prompt text, raw model completion, and parsed schema for any clicked trade, so that I can audit individual decisions down to the exact token.
14. As an AI engineer, I want live evaluation mode to execute $N=3$ variance sweeps over a budget-capped window of 20–30 decision points, so that I can measure output variance without exceeding API budgets ($< $5.00).
15. As a reviewer, I want the web dashboard to display a side-by-side metrics matrix comparing Total Return, Sharpe, Sortino, Max Drawdown, Brier Score, Latency, and Cost per 100 Decisions across all strategy variants and baselines.
16. As a frontend user, I want interactive comparative equity curve charts comparing LLM strategies directly against the Buy & Hold and SMA/RSI benchmarks, so that drawdowns and outperformance periods are visually obvious.
17. As an evaluator, I want telemetry tiles showing cumulative dollar cost, median latency (ms), and schema fallback rates, so that operational feasibility is benchmarked alongside financial performance.
18. As a data engineer, I want a seeding CLI (`pnpm seed:data`) that downloads historical bars from Alpaca/Yahoo and news headlines from Benzinga and freezes them into local JSON/Parquet fixtures, so that datasets can be refreshed on demand.
19. As a developer, I want all core indicators and backtest math unified into TypeScript within `apps/api`, so that the system eliminates multi-process orchestration overhead and cross-language serialization drift.
20. As a user, I want the web client to render genuine API responses without static UI mocks, so that all displayed data reflects real evaluation pipeline execution.

## Implementation Decisions

### 1. Monorepo Architecture & Pipeline Unification
- **Single-Stack Backend:** Fold indicator computation and execution simulation into `apps/api` (TypeScript), eliminating the un-wired `apps/quant` Python microservice. This unifies the entire execution loop under Vitest, pnpm, and Fastify, while preserving Wilder RSI and SMA-seeded EMA mathematical precision.
- **Service Topology:**
  - `apps/web`: React 18 + Vite + Tailwind + Recharts Observatory UI.
  - `apps/api`: Fastify 5 + Drizzle ORM + Zod + Anthropic SDK (Evaluation Engine, Lineage Store, Baselines, Data Ingest).
  - `packages/contracts`: Single source of truth for Zod schemas (API $\leftrightarrow$ Web $\leftrightarrow$ Manifests).
  - `packages/db`: Drizzle schema for manifests, decision lineage, frozen fixtures, and replay runs.
  - `packages/fixtures`: Pre-bundled zero-credential historical datasets (AAPL, NVDA, SPY for 2023–2024).

### 2. Temporal Data Layer & Anti-Leakage Guard (L0)
- All historical fact queries accept an explicit `asOf: Date | string` parameter.
- The `TemporalGuard` wraps all dataset accesses:
  $$\forall \text{record } r \in \text{Dataset}: \text{timestamp}(r) \le T_{\text{decision}}$$
  If $\text{timestamp}(r) > T_{\text{decision}}$, throw `TemporalIntegrityViolation`.

### 3. Pure Deterministic Baseline Suite (L1 & L2)
- **Baseline A (Buy & Hold):** Long 100% equity allocation from start to finish.
- **Baseline B (SMA 20/50 + RSI 14):**
  - Bullish: $\text{SMA}(20) > \text{SMA}(50)$ and $\text{RSI}(14) < 70$.
  - Bearish: $\text{SMA}(20) < \text{SMA}(50)$ or $\text{RSI}(14) > 70$.
  - Neutral / Cash: All other states.
- **Simulation Rules:** Fill at open of bar $T+1$; 5 bps transaction fee on turnover; realistic cash accounting.

### 4. Consensus, Debate & Ablation Harness (L3 & L4)
- **Specialist Fan-Out:** Technical Specialist (indicators) + Sentiment Specialist (Benzinga headlines $\le T$) + optional Polymarket Macro Specialist.
- **Consensus Rule:**
  - If $\text{bias}_{\text{tech}} == \text{bias}_{\text{sent}}$, output consensus signal immediately (Short-Circuit: 0 extra tokens).
  - If disagreement:
    - **Debate Mode (ON):** Invoke 1-pass synthesis prompt with both specialist rationales and record synthesis output.
    - **Ablation Mode (OFF):** Emit neutral signal (`bias: neutral, confidence: 0.0`) deterministically without LLM call.

### 5. Experiment Manifest & Lineage Store (L5)
- Every experiment run generates an immutable manifest:
```typescript
interface ExperimentManifest {
  id: string;
  createdAt: string;
  gitCommit: string;
  datasetHash: string;
  ticker: string;
  timeframe: { start: string; end: string };
  strategyConfig: {
    mode: "replay" | "live";
    modelId: string;
    temperature: number;
    debateEnabled: boolean;
    polymarketEnabled: boolean;
  };
  metrics: {
    totalReturn: number;
    annualizedReturn: number;
    sharpeRatio: number;
    sortinoRatio: number;
    maxDrawdown: number;
    turnover: number;
    tradeCount: number;
    directionalAccuracy: number;
    brierScore: number | null;
    abstentionQuality: number;
    costUsd: number;
    medianLatencyMs: number;
    fallbackRate: number;
  };
  baselineMetrics: {
    buyAndHold: FinancialMetrics;
    smaRsi: FinancialMetrics;
  };
}
```
- Lineage DAG records exact point-in-time state: `{ decisionId, asOf, inputBars, indicators, news, rawPrompt, rawCompletion, parsedSignal, executionFill }`.

### 6. Observatory & Tearsheet UI (L6)
- **Comparison Tearsheet:** Side-by-side delta table (`Strategy vs Buy&Hold vs SMA/RSI`).
- **Equity Curve Multi-Series Chart:** Visualizing strategy trajectories with drawdown bands.
- **Decision Lineage Inspector:** Interactive timeline clicking through any bar to view the prompt, reasoning, and market context.
- **Telemetry HUD:** Cost per 100 decisions, median latency, and fallback counts.

## Testing Decisions

### Seam Architecture (The High Seams)
1. **Primary Seam: The Evaluation Engine Orchestrator (`runExperiment(config)`)**
   - Inputs: Fixture dataset identifier, strategy configuration (model, debate toggle, baselines).
   - Outputs: Complete `ExperimentManifest` with simulation equity curves, metrics, and lineage records.
   - External behavior tested: Verifies returns, Sharpe, drawdown, cost calculations, consensus routing, and ablation neutrality.
2. **Secondary Seam: Temporal Guard & Anti-Leakage (`TemporalGuard.query(asOf)`)**
   - Asserts strict boundary enforcement across all data adapters.

### What Makes a Good Test
- Tests must assert observable domain outcomes (equity curves, Sharpe ratios, directional signals, latency tracking), never internal LLM prompt wording.
- All baseline calculations and indicator math must be validated against deterministic reference fixtures.
- Zero flaky tests: Offline replay tests must run with frozen fixtures and mock completions with 100% determinism.

### Test Matrix
- `tests/anti-leakage.test.ts`: Deliberately injects future records and asserts `TemporalIntegrityViolation`.
- `tests/indicators.math.test.ts`: Verifies mathematical parity for Wilder RSI, EMA seeding, and Bollinger standard deviations.
- `tests/baselines.simulation.test.ts`: Verifies 1-bar delay, 5 bps fee calculation, and Buy & Hold / SMA logic.
- `tests/consensus.ablation.test.ts`: Verifies short-circuiting on agreement and neutral fallback when debate is disabled.
- `tests/manifest.lineage.test.ts`: Verifies JSON manifest generation and full lineage provenance integrity.
- `tests/replay.cli.test.ts`: Verifies `pnpm demo:replay` completes in $< 3.0$ seconds without network access.

## Out of Scope

- Live/paper brokerage trading via Alpaca WebSocket order execution.
- Real-time trading bot interfaces, chat commands (`/trade`, `/portfolio`), or push notifications.
- Multi-round unbounded conversational debates beyond a single synthesis step.
- Vector database episodic memory / long-term embeddings (deferred to post-evaluation extensions).
- Marketing claims or live financial advice disclaimers.
